Users and Access

Users

With no users, SQ is open on your network. Add the first user (an admin) to turn on logins. Everyone shares the same boards; roles decide who can change what.

API keys

For Home Assistant and scripts. A key acts with the role you give it (member can act, viewer can only read) and is sent as an X-API-Key header. The key itself is shown once, when you create it. Ready-made HA configuration lives in homeassistant/sq.yaml in the repo.

Setting up a screen

  • Raspberry Pi: run scripts/pi-display-setup.sh on the Pi (Raspberry Pi OS Lite is enough). It installs a minimal kiosk that boots straight into this display and restarts it if anything crashes. Pass the display URL from the table above.
  • ESP32: flash the ESPHome config in examples/esphome-tdisplay.yaml (LILYGO T-Display) or examples/esphome-display.yaml (generic), pointing it at the API URL above.
  • Android TV: enable Developer options and Network debugging on the TV, add it here with its IP, then press Show. The first Show pops an "allow USB debugging" prompt on the TV: tick Always allow. The TV needs a browser that can open links (most Google TVs ship Chrome; sideload one otherwise).

Claude Code connector

Feeds the Claude Code dashboard. Run the connector on each machine where Claude Code works:

python3 claude-code-connector.py \
  --url {{ base_url }} \
  --token {{ connector_token }}

The script is scripts/claude-code-connector.py in the repo. It posts a status snapshot every 60 seconds; add --interval 30 to report faster, or install it as a service with --install (systemd). It reads Claude Code's local session files and each repo's .beads/issues.jsonl; nothing else leaves the machine.
